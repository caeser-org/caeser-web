B1 packages the current Go investigation engine as a single, readable build for
early adopters. Caeser starts from failed CI evidence, connects it to the exact
source revision, traces failure locations and values, and produces an
evidence-linked investigation report. The report can be continued by a developer
or another coding assistant.

## What it does

- The default GitHub Actions path analyzes existing failure logs and artifacts,
  then publishes a report and pull-request comment.
- Optional paths can reproduce failures, compare base and head, run bounded Go
  probes, invoke a configured model through the evidence harness, or propose and
  verify a repair.
- Investigation state records evidence, hypotheses, actions, experiments, and
  verification results. Reports distinguish observed facts from inferences and
  unresolved questions.

The optional paths are not all enabled by the default CI integration. Model
analysis is bounded and does not override deterministic findings. Leads are
starting points, not guaranteed root causes or fixes.

## Evaluation status

Existing results are development-exposed. The latest ten-case rerun produced
three exact-function hits and one abstention, and confirms reproducibility of
that evaluation pipeline. It is not an independent accuracy estimate. B1 makes
no accuracy or time-savings guarantee for unfamiliar failures.

## Build

Build from the repository root with Go 1.26 and CGO enabled:

```sh
CGO_ENABLED=1 go build -trimpath -o caeser ./cmd/caeser
```

See the [README](https://github.com/caeser-org/ceaser/blob/main/README.md), [architecture guide](/docs/runtime-architecture/),
and [capabilities and limits](/docs/capabilities/) for setup and details.
