This release ships the candidate-admission fix from commit `4a5c4d9` on top of
v0.1.0. It changes how existing evidence is admitted and ranked. It does not
change any verification gate, promotion rule, or abstention rule.

## What changed

- Functions named by causal-chain `assertion_dependency` and
  `implementation_branch` steps are now admitted as `causal_dependency` leads.
  Assertion-dependency steps form a path from the failing assertion toward the
  value's origin, so later steps rank higher. Previously these functions were
  found by the chain and then dropped at candidate admission.
- A function named at the failing assertion in retrieved test source is admitted
  as an `assertion_mention` lead, limited to comments with explicit causal
  language. The report cites the exact evidence ID.
- A function already present in the candidate tier is no longer re-injected from
  SSA with a competing rank. Operand distance can no longer override the
  evidence-grounded order.

All leads remain investigation leads. None is promoted to a verified root cause.

## Measured results, stated precisely

| Set | Cases | Exact-function matches | Status |
|---|---:|---:|---|
| Paired development cases | 6 | 6 of 6 with tracing enabled, 5 of 6 without | Development-exposed |
| Five verified regressions from unfamiliar repositories | 5 | 3 of 5 after the fix, originally 1 of 5 | Development-exposed after tuning |

The five cases were used to diagnose and fix the admission gap. They are no
longer independent. **There is no fresh independent accuracy measurement.**
The full history is in `evaluation/final-mission/INDEPENDENT-RESULTS.md`.

## What this release does not claim

- No claim of production-ready root-cause diagnosis. Caeser remains an
  investigation tool that establishes what evidence shows and ranks functions
  worth inspecting.
- No claim that 6 of 6 or 3 of 5 generalizes to unfamiliar code. Both figures
  are on cases that informed development.
- No change to verification gates. Runtime verification remains narrow and
  experimental.

## Get started

Build from source with Go 1.26:

```sh
git clone https://github.com/caeser-org/ceaser.git
cd caeser
go build -o caeser ./cmd/caeser
./caeser version
./caeser init
./caeser evidence --ci-log failed.log > report.json
./caeser brief --report report.json
```

For continuous integration, use the reusable workflow documented in
`docs/ci-integration.md`, pinned to `v0.1.1`.
